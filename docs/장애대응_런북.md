# FLIT WAIT 장애 대응 런북 (현장용)

> 행사 당일 문제가 생겼을 때 **증상 → 1분 판단 → 조치** 순서. SQL 은 Supabase 대시보드 > SQL Editor (프로젝트 `flit-wait`).
> 원칙: ① 손님 앞에서는 종이·육성으로 먼저 해결 ② 그다음 시스템 ③ 데이터는 지우지 말고 상태만 바꾼다.

## 0. 30초 상태 점검 (아침 · 이상 징후 때)

**가장 빠른 방법 (폰에서도 됨)**: https://wait.flitunion.com/api/health 를 연다. `"ok": true` 면 정상, `503` + `problems` 배열이 뜨면 그 문구가 곧 증상이다(아래 §3·§4 로).
- 보는 것: cron 최근 실행(3분 내), cron 활성, 발송 큐(예정 지난 미발송·1시간 실패·멈춤), 발송 함수 마지막 응답, 열린 행사, 성남 부스 일시중단, 오늘 티켓 수. 개인정보 없음.
- **자동 점검 루틴** (클라우드, 2026-10-20 설정): 10/23~25 매일 08:30·12:30 KST 에 위 주소와 손님 목록 API, 화면 3개를 점검해 보고를 남긴다. 결과: https://claude.ai/code/routines (이름 "FLIT WAIT 성남 행사 아침/정오 점검"). 행사 후 두 루틴은 끄기(안 끄면 내년 10월에 다시 돈다).

SQL 로 직접 볼 때:

```sql
select 'cron' k, string_agg(jobname||'='||active::text, ', ') v from cron.job
union all select 'cron_last', max(start_time)::text from cron.job_run_details
union all select 'notify_http', (select status_code::text||' '||left(content::text,40) from net._http_response order by created desc limit 1)
union all select 'pending', count(*)::text from notifications where status='pending'
union all select 'failed_1h', count(*)::text from notifications where status='failed' and created_at > now()-interval '1 hour'
union all select 'sending_stuck', count(*)::text from notifications where status='sending' and sent_at < now()-interval '3 minutes';
```
정상: cron 둘 다 `true`, cron_last 가 1분 이내, notify_http `200`, pending 수십 이하, failed/stuck 0.

## 1. 손님 쪽 증상

| 증상 | 원인 후보 | 조치 |
|---|---|---|
| QR 찍으면 "행사를 찾을 수 없습니다" | 행사 status 가 `draft`/`closed` | 관리자 > 행사 설정 > 상태 `open` |
| 목록은 뜨는데 "지금은 운영 시간이 아닙니다" | 행사 시작·종료 시각 | 관리자 > 행사 설정에서 시각 수정 (KST 로 입력) |
| 접수 버튼 눌러도 "접수가 일시 중단" / "오늘 접수가 마감" | 스태프가 일시중단 또는 오늘 마감 켬 | 스태프 화면 "접수 재개". 오늘 마감은 자정에 자동 해제 |
| "오늘 접수가 마감되었습니다" | 행사 종료 30분 전 (`queue_close_before_min`) | 의도된 동작. 더 받으려면 관리자 > 부스 설정 값 줄이기 |
| 쿠킹 회차가 전부 "오픈 전" | 매일 12:00 오픈 규칙 | 정상. 12:00 전엔 그렇게 보임. 조기 오픈이 필요하면 부스 설정 "일별 예약 오픈 시각" 비우기 |
| 회차가 "예약 마감 · 현장 대기" | 시작 15분 전 지남 | 정상. 스태프가 "현장 손님 추가"로 입장 처리 |
| 손님이 알림톡을 못 받음 | 카카오 미가입/차단 → SMS 대체, 번호 오타 | 관리자 > 발송 로그에서 해당 건 `sent/failed` 확인. `/t/토큰` 화면은 자동 갱신되니 화면으로 안내. 재호출 버튼으로 재발송 |
| 같은 번호로 다시 접수 안 됨 | 부스당 1건 규칙 | 기존 건을 스태프가 노쇼/삭제 후 재접수. 또는 부스 설정 "같은 번호 중복 접수 허용" |
| 취소 버튼이 없음 | 취소 마감 지남(쿠킹 30분 전) 또는 이미 호출됨 | 정상. 스태프 화면에서 노쇼/취소 처리 |
| 화면이 안 열림 (전체) | Vercel 또는 Supabase 장애 | §4 로 |

## 2. 스태프 쪽 증상

| 증상 | 조치 |
|---|---|
| PIN 이 안 맞음 | 관리자 > 부스 > PIN·QR 탭에서 **재설정** (기존 PIN 은 조회 불가). 재설정하면 다른 폰의 세션도 끊기니 모두 재로그인 |
| "스태프 인증이 만료되었습니다" | PIN 이 바뀐 것. 로그아웃 → 새 PIN 으로 |
| 호출했는데 손님 알림이 안 감 | 1) 대리 접수 손님은 번호가 없어 원래 안 감 2) 발송 로그 확인 3) 재호출 |
| 입장 처리를 잘못 눌렀다 | 카드의 **되돌리기** → 미도착(waiting) → 다시 노쇼/입장 |
| 노쇼를 잘못 눌렀다 (대기표) | 처리 내역 ▼ 펼치기 → **대기로 복구** (원래 순서로 맨 앞) |
| 노쇼 손님이 늦게 왔다 | 카드의 **지금 입장** (회차는 정원 남은 경우만) |
| 현장 손님 추가가 "정원 초과" | 정상. 다음 회차로 안내하거나 관리자에서 회차 정원 상향 |
| 폰 배터리/통신 끊김 | 다른 폰에서 같은 PIN 으로 로그인 (동시 여러 대 가능) |
| 화면 숫자가 몇 초 늦음 | 폴링 5~12초. 정상 |
| 스태프 화면 자체가 안 열림 | 종이 번호표 + 육성 호출로 전환. 복구 후 "대리 접수"로 기록 |

## 3. 알림 발송 장애

### 3-1. pending 이 계속 쌓임 (발송 함수가 안 돎)
```sql
select * from net._http_response order by created desc limit 5;      -- notify 호출 응답
select * from cron.job_run_details order by start_time desc limit 5;  -- cron 실행
```
- `_http_response` 가 403 → Edge Function secret `CRON_SECRET` 와 Vault `cron_secret` 불일치.
- 응답 없음/5xx → Supabase 대시보드 > Edge Functions > notify > Logs 확인. 함수 재배포: 저장소 `supabase/functions/notify/index.ts` 를 MCP `deploy_edge_function` 또는 CLI 로.
- 수동 1회 실행:
  ```sql
  select net.http_post(url := 'https://mqrafomyngxsixakbnzu.supabase.co/functions/v1/notify',
    headers := jsonb_build_object('x-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name='cron_secret')));
  ```

### 3-2. failed 가 늘어남
```sql
select template_code, left(error,160), count(*) from notifications where status='failed' and created_at > now()-interval '1 hour' group by 1,2 order by 3 desc;
```
| 오류 문구 | 의미 | 조치 |
|---|---|---|
| `3015` 템플릿 없음 / `templateCode` | NCP 템플릿 코드 불일치 또는 미승인 | `templates.ncp_template_code` 와 NCP 콘솔 코드 대조. BrandMessage 가 아니라 **AlimTalk Template** 에 있어야 함 |
| 본문/버튼 불일치 | 승인 본문과 글자 다름 | `templates.alimtalk_content`/`button_name` 을 NCP 승인본과 글자 단위로 맞춤 |
| 일 한도 초과 | 일 10,000건 초과 | NCP 콘솔 > 한도 관리 상향 요청. 그동안 SMS 로 자동 대체되지 않으니 현장 육성 호출 병행 |
| 잔액 부족 | NCP 선불 소진 | 충전 |
| 발신번호 오류 | SMS 대체 발신번호 미등록 | `NCP_SMS_FROM` secret 확인 |
실패 건은 2분·4분 뒤 자동 2회 재시도된다. 원인 고친 뒤 그래도 남은 failed 를 다시 보내려면:
```sql
update notifications set status='pending', attempts=0, scheduled_at=now() where status='failed' and created_at > now()-interval '1 hour';
```

### 3-3. 오발송이 의심될 때 (즉시)
1. 행사 상태를 `closed` 로 → 새 접수·예약 차단 (기존 티켓 조회는 됨).
2. 대기 중 알림 중단: `update notifications set status='skipped' where status='pending';`
3. 원인 파악 후 `open` 으로 복구. 테스트는 반드시 `test` 행사 + **010-00xx-xxxx 번호**(실발송 안 됨)로.

### 3-4. 특정 손님에게 수동으로 다시 보내기
```sql
select enqueue_notification((select id from tickets where token='<토큰>'), 'Q03');  -- 코드: Q01~Q06, R01~R05
```

## 4. 서버·인프라 장애

| 증상 | 확인 | 조치 |
|---|---|---|
| 사이트 전체 안 열림, Vercel 상태 | https://vercel.com > flit-wait > Deployments | 최근 배포 실패면 이전 배포 **Promote to Production** |
| 화면은 뜨는데 데이터 안 옴 | Supabase 대시보드 > 프로젝트 상태 | `Paused` → Restore. `Restarting` → 1~2분 대기 |
| "too many connections" | Small 컴퓨트 한도 90 | 대기표 폴링 간격 상향(`MyTicket.tsx` base 값) 후 배포, 또는 Compute Medium |
| 느림 (p95 > 1s) | 대시보드 > Reports > Database CPU | CPU 60% 이상이면 Compute 한 단계 상향 (재시작 1~2분 — 손님 적은 시간대에) |
| 스케줄러가 노쇼를 안 돌림 | `select run_scheduler();` 수동 실행 → 반환 JSON 확인 | cron 이 꺼졌으면 `select cron.alter_job(jobid, active := true)` |
| 대기번호가 어제 번호에 이어짐 | `ticket_date` 가 KST 자정 기준 | 정상이면 날짜별 리셋. 아니면 `kst_today()` 확인 |

## 5. 데이터 수동 조치 (관리자 화면으로 안 될 때)

```sql
-- 티켓 상태 되돌리기 (삭제 금지)
update tickets set status='waiting', called_at=null, checked_in_at=null where token='<토큰>';
-- 회차 정원 늘리기
update slots set capacity = 24 where id = '<slot uuid>';
-- 회차 닫기(예약 차단, 기존 예약 유지)
update slots set status='closed' where id = '<slot uuid>';
-- 부스 설정 한 항목만 바꾸기
update booths set settings = settings || '{"call_valid_min": 7}'::jsonb where slug='tech-1';
-- 행사 긴급 중단 / 재개
update events set status='closed' where slug='seongnam-2026';
update events set status='open'   where slug='seongnam-2026';
```
